# Vibe Coding Glossary

The methodology and philosophy behind the workshop's approach to learning programming.

## The Core Philosophy

- **[Vibe Coding](./vibe-coding.md)** — The overall approach and philosophy

## The Four Practices

These are the concrete practices that make vibe coding work:

1. **[Specification](./specification.md)** — Clearly state what should happen
2. **[Verification](./verification.md)** — Check that it actually happens
3. **[Iteration](./iteration.md)** — Refine through repeated cycles
4. **[Selective Reading](./selective-reading.md)** — Read code strategically

## The Workflow

```
Specify → Generate → Verify → Iterate
   ↑                              ↓
   └──────────────────────────────┘
```

Each term represents a phase:

**Specification:** Define what you want
- Clear inputs, outputs, constraints
- Success criteria

**[AI Generation]:** Get code from AI
- Clear prompts based on specification

**Verification:** Check it works
- Test with known inputs
- Apply domain knowledge
- Verify against specification

**Iteration:** Refine and improve
- Fix what's wrong
- Add features incrementally
- Build on what works

## Why This Works

This approach is effective because it mirrors how:

**Humanities scholars work:**
- Specify research questions clearly
- Gather evidence (don't read everything)
- Verify claims against sources
- Iterate on arguments

**Musicians learn:**
- Hear a song (experience)
- Play by ear (reproduce)
- Practice and refine (iterate)
- Learn theory later (selective understanding)

**Drivers operate cars:**
- Specify destination
- Drive (without understanding engine)
- Verify you're going the right way
- Adjust course as needed

## What Makes This Responsible

This isn't "trust blindly." It's systematic verification:

| Traditional Coding | Vibe Coding |
|-------------------|-------------|
| Understand → Build | Build → Verify |
| Comprehension = Trust | Testing = Trust |
| Know how it works | Know that it works |
| Deep before broad | Broad before deep |

Both are valid. Vibe coding is optimized for:
- Quick competence over deep mastery
- Doing over understanding (initially)
- Practical results over theoretical knowledge

## The Learning Path

**Week 1:** Everything feels weird
- "I don't understand what's happening"
- "This feels like cheating"

**Week 3:** Patterns emerge
- "Oh, this is a loop"
- "I've seen this before"

**Month 2:** Selective understanding
- You know what matters
- You know when to go deeper
- You're productively using code

**Month 6:** Hybrid fluency
- Vibe coding for speed
- Traditional learning for depth
- Best of both worlds

## Critical Success Factors

Vibe coding works when you:

✓ Write clear specifications
✓ Verify rigorously
✓ Iterate incrementally
✓ Read selectively but carefully
✓ Know your limits

It fails when you:
✗ Skip verification
✗ Try to understand everything first
✗ Don't specify clearly
✗ Trust without testing
✗ Never learn deeper
